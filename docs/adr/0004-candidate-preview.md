# ADR 0004: Isolated candidate onboarding preview

The next slice is a synthetic invitation-to-form-review journey. HR creates a scoped intake record and rotates/revokes 72-hour invitations. A candidate deliberately requests an email code, exchanges invitation/code for an isolated session, autosaves a minimal versioned form and submits an immutable snapshot. HR requests corrections or approves that form. Completed employment activation remains gated by the additional identity, document, task, policy and leave prerequisites.

Use a separate listener and portal, `http://127.0.0.2:5174`, with the API privately bound at `127.0.0.1:4001`. A second port on the employee host would not isolate host-only cookies. Candidate cookies are HttpOnly, Strict, host-only and never accepted by employee middleware. The candidate database login has no employee/identity/platform grants. Fixed NOLOGIN-owner functions handle invitation/OTP/session lookup; candidate form queries use transaction-local case context and FORCE RLS. HR uses its existing session, CSRF, entity scope and a separate onboarding permission.

Real mail/provider configuration is unavailable. Both candidate and HR onboarding surfaces are therefore development/demo-only, and nominated addresses must end in `@anvi.example`. An encrypted, expiring development delivery tray holds the invitation/code message; only assigned HR may inspect it, with an audit event. This is a local transport preview, not evidence of email ownership or external delivery. Candidate production startup is rejected. Real delivery, retention approval and provider verification must replace the tray before enablement; never silently fall back to it.

Invitation/session tokens are random 256-bit values; credential tables retain hashes. Short-lived OTPs are HMAC-protected with the preview secret, limited to five attempts and throttled by invitation and source IP. The temporary delivery payload is AES-256-GCM encrypted and removed on exchange/rotation/revocation. Tokens enter the browser through a URL fragment, are immediately moved into memory and removed from the address bar, and are never placed in browser storage. GET does not consume an invitation. Correct verification consumes it once atomically; replay cannot create another session. Rotation revokes old challenges/sessions and preserves drafts.

The initial form collects only preferred display name, a professional introduction and a preview notice acknowledgement. No documents, bank/tax, private contact or health fields are introduced. Submission locks editing; changes requested reopens it. Optimistic versions prevent stale saves/reviews; immutable submission snapshots retain before/after review history. Approval grants no employee access and allocates no employee code.

Enforcement: strict shared schemas; scoped FKs/RLS and column grants; transactional case/audit/outbox writes; API tests for role/entity/cookie boundaries, scanner GET, wrong/replayed OTPs, expiry, rotation, revoked sessions, concurrency and rollback; browser journey across both origins, correction/resubmission, mobile/keyboard/axe checks. Existing employee regression suites remain required. Local credential setup, repeatable migration/seed, build scripts, runbooks and traceability are updated together. Rollback is feature disablement/forward correction; preserve submission/audit history.

Design: keep Atlas typography and graphite/emerald surfaces for the HR pipeline; use a calm paper-and-celadon candidate workspace with a clear progress rail, saved state and one primary action per step. Avoid decorative HR metrics or simulated delivery-success claims. The first sketch of a shared employee/candidate login was rejected because it obscured the security and user-role distinction.

References: [OWASP token/code handling](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html) and [session/cookie boundaries](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html). This preview does not complete the master plan's full onboarding/activation acceptance.
